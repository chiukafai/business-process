# 业务登记协同系统

把《业务登记模板.xlsx》升级成多人协同的网页台账：各地部门异地登录、按人分配权限、状态一目了然、上游处理完下游自动出现在待办里，并可推送企业微信提醒。

技术栈：Python 3 + Flask + SQLite(WAL)，模板 Jinja2，无前端构建步骤。

## 零、克隆与参与开发

```bash
git clone git@github.com:chiukafai/business-process.git
cd business-process
pip install -r requirements.txt
python app.py
```

> 国内网络访问 `https://github.com` 常被阻断，但 SSH 通，所以仓库远端用的是 SSH
> （`git@github.com:chiukafai/business-process.git`）。首次使用请确认本机 SSH 公钥已加到 GitHub：
> `ssh -T git@github.com` 返回 `Hi <你的用户名>!` 即正常。

## 二、初始化顺序（第一次用）

1. 用 admin 登录 → 改密码
2. 「部门」→ 添加各经营主体（广州分公司、成都分公司……），可设简称和排序
3. 「人员与权限」→ 逐个添加人员：姓名、用户名、手机号、归属部门、角色、企业微信 userid
   - 初始密码默认 `Hailu@2026`，把账号密码发给对方
   - 对方首次登录会被要求改密
4. 需要临时加权限的人，点「权限」单独勾选；权限区顶部有「全选」，也可以一键全给再单独取消

## 三、角色与默认权限

| 角色 | 默认能做什么 |
|---|---|
| 业务员 | 登记自己的业务、导入自己的数据、查看客户档案 |
| 主管 | 登记、看本部门全部业务、导出 |
| 财务 | 看全部部门、登记收款 / 费用 / 录回单、确认开票、退回修改、导出 |
| 管理员 | 全部权限 + 人员管理 + 部门维护 + 操作日志 + 系统设置 |

角色只是"默认勾选包"，勾选框里的权限才是真实判定。给某个人单独勾掉或加上都不会影响别人。

## 四、一笔业务怎么走

```
报批中 → 提交 → 待收款 →（收到部分款）收款中 →（收齐）待开票 →（财务确认）已开票
          ↘ 财务退回 → 已驳回 → 修改后重新提交
          ↘ 业务员撤回 → 回到报批中
          ↘ 登记时选「不要开票」→ 收齐后直接是「已收齐·无需开票」
```

**流程阶段**（列表「阶段」列、详情页顶部标签、仪表盘分布、导出「流程阶段」列统一用它）：

| 阶段 | 数据库 status | 含义 / 下一步归谁 |
|---|---|---|
| 报批中 | `draft` | 已登记，等登记人补确认（部门、是否开票）后提交 |
| 待收款 | `pending_payment`（一分未收） | 等资管确认客户款项是否到账 |
| 收款中 | `pending_payment`（已收部分） | 资管继续追收，收到后逐项登记 |
| 待开票 | `completed` + 要开票 + 未开票 | 款项已收齐，等财务开票 |
| 已开票 | `completed` + 已开票 | 收齐且发票已开出，流程结束 |
| 已收齐·无需开票 | `completed` + 登记时选了不要 | 收齐即结束，不进财务待办 |
| 已驳回 | `rejected` | 被退回，修改后可重新提交 |

> 数据库 `status` 仍是四态（`draft / pending_payment / completed / rejected`），
> 「待开票 / 已开票 / 无需开票」都由 `completed` 派生——**收齐未开票 ≠ 已开票**，
> 只看 status 会把三种情况都显示成「已收齐」，所以展示层单独派生阶段。
> 筛选、导出、仪表盘统计共用 `utils.STAGE_SQL`，与 `stage_of()` 一一对应。

- **报批中**：登记或导入后的初始状态，可继续改；**归属部门**与**是否开票**两项没确认的单据不能提交
  （导入的单据开票口径可能是空的，详情页顶部会出现「待确认：是否需要开票」卡片，选一次即可）
- **待收款 = 资管的活**：进入待收款后提醒的是**资管部门**（收款确认部门，可在系统设置里改），
  业务员这一步**不被告知**，避免两头催；资管每确认一轮收款，系统再回头通知登记这笔业务的业务员
- **收款按项目分别填列**：贸易费 / 留存利润 / 资金过夜费 三栏（这三项是应收），
  另有渠道提成 / 财务费用 / 其他费用三栏只做随款留痕、不参与应收；
  页面顶部「本次合计」实时算；「按待收全额填入」可一键把各项待收填满
- 收款可分批登记：各项全留空=还有款没收；各项都填 0=主管特批结清（需 `record.close_short` 权限）；
  **三项应收各自收满**才自动结清——只填了贸易费、留存利润一分没收的单，仍挂在待收款；
  收满后按开票口径落到「待开票」或「已收齐·无需开票」
- **开票在登记时选「要 / 不要」**：选「要」的，收齐后轮转到财务（财务部，权限 `record.invoice`）
  确认**已开票**，此时阶段从「待开票」变为「已开票」；选「不要」的自动跳过开票环节，不进财务待办
- 收齐后由财务做费用登记（渠道提成 / 资金过夜费 / 财务费用 / 其他费用四项）
- 提交后内容锁定，业务员要改必须先撤回（还没收款时）或被财务退回
- 节点变化会自动提醒下一步负责人（企业微信 + 站内「我的通知」，见第七节），同时进「我的待办」
- **待办按「轮到谁」出现，不按「谁能看」铺开**：待收款跟进只在**主管**的待办里（看本部门进度）：
  - 资管 → 只看「待我确认收款」（全公司，这是他的活）
  - 主管 → 「待收款跟进」（本部门别人的待收款，可协助）
  - 财务 → 只看「待我确认开票」（收齐且登记选了「要」才出现），不再被别人的待收款占着
  - 业务员 → 自己的「待我修改 / 我的报批中」+ 收款到账进度
- **时间按月份登记**：表单是「年 + 月」两个下拉（1-12 月），数据库存当月 1 日，
  列表 / 详情 / 导出 / 筛选都按月显示，不再填具体日期
- **费用类型**在「金额核算」区填，目前只登记、不参与金额计算，公式待后续定

## 五、金额口径（当前设置）

| 字段 | 口径 |
|---|---|
| 贸易费 | 业务金额 × 费率 ÷ 100，**默认按公式自动算，可手工修正**（四舍五入差异、谈定的实际费用） |
| 留存利润 | 导入贸易计划时取 **K 列（表头「利润1」）的合计项**；可手工修正 |
| 资金过夜费 | 费用明细里的「资金过夜费」，**计入应收** |
| 应收合计 | 贸易费 + 留存利润 + 资金过夜费（三项彼此独立，互不扣减） |
| 公司实收 | 累计已收（实际到账，由收款流水累计） |
| 待收金额 | 应收合计 − 预存金额 − 已收金额（允许负数，界面标红） |

- 费率填 `1.5` 表示 1.5%
- **贸易费的修法**：表单里默认自动算出（跟着业务金额 / 费率联动），要改就直接改这个框；
  改过之后框下的提示会显示「公式值 X，当前差 Y」，点旁边的「按公式」即可回到自动值。
  收款登记重算待收时**不会**把手工值覆盖回公式值
- **三项应收各自收齐**才进下一步；未收齐就结清属特殊情况，需主管特批（`record.close_short`）
- 费用明细四项里的**资金过夜费计入应收**；渠道提成 / 财务费用 / 其他费用只登记，不参与计算
- 收款时按项目填列：某项超收不抵扣其他项，所以「待收」显示的是真正还差的合计；
  各项都收满但总共多付时，待收显示负数（标红）
- 金额在数据库里存整数分，不会有小数误差
- 「辅助核算费用」列已停用（`aux_fee_cents` 仅保留历史值）。改口径只需动 `utils.py` 的 `calc_amounts`

## 六、客户档案与 Excel 导入

- 入口：左侧「客户档案」（需要「查看客户档案」权限）
- 字段里的「主体公司」对应贸易计划模板的同名字段（旧版叫「简称」，导入时两种表头都认）
- 登记业务时客户名可从下拉选已有客户，直接输入新名称会**自动建档**
- 支持 Excel 批量导入：左侧「导入客户」→ 下载模板 → 上传
  - 必需列只有「客户名称」，其余按表头名称自动识别，列序不限
  - 同名客户走更新（用非空值覆盖，空值保留原值）
  - 文件内重复名、空名称、超 100 字会被跳过并列出原因
- 客户改名后，历史业务里的客户名称会同步更新
- **删除**：该客户名下没有业务记录时才允许删除；已有业务只能「停用」，历史数据完整保留
- **批量操作**：每行左侧勾选框，表头与工具条各一个「全选」，支持「反选」、Shift 连选
  - 「批量停用」「批量启用」「批量删除」三个动作共用一次勾选，已选数量实时显示
  - 批量删除会逐家校验：有业务记录的客户被跳过并计数提示（提示里给出前 3 家名字）
  - 只读权限（只有「查看客户档案」）的人能看到列表，但勾选框与按钮均为禁用态

### 发票额度

- 每个客户可设「发票额度」（按元填），列表里同时显示额度、已开票金额、剩余额度
- 已开票金额 = 该客户名下所有勾了「已开票」的业务金额合计，系统自动算，不用手填
- 剩余为负时标红，提示已经超额
- 导入客户时加一列「发票额度」即可批量设置；该列留空表示这一行不修改额度

### 业务导入：两种模板都认

| 系统字段 | 业务登记模板的表头 | 贸易计划模板的表头 |
|---|---|---|
| 客户名称 | 客户名称 | **主体公司** |
| 业务金额 | 业务金额 | **金额**（F 列） |
| 留存利润 | 留存利润 | **利润1**（K 列合计） |
| 月份 | 月份 / 时间 | —（落为当前月） |

- 表头只需认出「客户名称类」和「金额类」两列，其余按名称自动识别，列序不限
- 表头可以在前 15 行内的任意位置，上面有标题行也不影响识别
- **含合计 / 汇总 / 小计公式的行会自动跳过**（SUBTOTAL 行取到的是结果值，看不出是合计，所以会再读一次公式来判断）
- 归属部门只看两处：表格里有「归属部门」列就以表格为准，否则按**客户档案里该主体公司挂的部门**；
  两处都没有时**留空待确认**（不按导入人的部门归属），需在业务详情里选好部门才能提交进入收款；
  确认部门时会顺带回填客户档案，下次导入自动带出
- 贸易费：表里带「贸易费 / 应收金额」列就**以表里的值为准**（四舍五入取整差异以表内数为准），
  没有这列或单元格空着才按公式算；两者差异超过 1 分会在结果页提示，方便核对
- **导入前必须确认本批「是否开票」**：上传页有「要开票 / 不开票」必选项——
  贸易计划模板根本没有这一列，不选就不让导入（否则单据带着空开票口径一路走到收齐，财务才知道该不该开票）；
  表内若自带「是否开票」列，**以表内为准**，与本批选择不同的行会在结果页告警
- 导入完成后，结果页会明确列出：本批开票口径、跳过哪几行、哪些列没被导入、缺费率时贸易费按 0 算、留存利润取的是哪一列
- 客户名按「客户名称」匹配，匹配不到再按「主体公司」列匹配，都没有才新建档案，避免重复建档

## 七、企业微信通知（自建应用）

1. 企业微信后台建自建应用，拿到 corpId / agentId / secret
2. 应用详情里把服务器的**公网出口 IP** 加进「企业可信 IP」
3. 系统内：「系统设置」→ 填三个凭据 → 勾选「启用」→ 保存 → 发一条测试消息
4. 「人员与权限」里给每个人填企业微信 userid（不填的人收不到）

触发节点：

| 事件 | 通知谁 | 消息内容要点 |
|---|---|---|
| 业务提交 | 收款确认部门（资管）的人员 | 应收合计 = 贸易费 + 留存利润，请确认到账 |
| 每确认一轮收款 | 登记这笔业务的业务员 | 本轮已收多少、尚待收多少 |
| 收款收齐 | 业务员 + 有「开票确认」权限的财务（**仅登记时选了「要」**） | 需开票则提示财务确认开票；选「不要」的只告诉业务员流程结束 |
| 财务退回 | 提交人 | 退回原因，改完可重新提交 |

- 业务员在「待收款」这一段不被告知，避免和资管两头催；收齐这一步才会回到业务员身上
- 选「不要」开票的单据，收齐后不进财务待办、也不提醒财务，流程直接结束
- 收件人取「人员与权限」里填的企业微信 userid，没填的人自动跳过（不报错）
- **站内通知**：同一批通知同时写进系统的「我的通知」（侧边栏，带未读数）。
  企业微信没配置、或某人没填 userid 时，登录后照样能看到「哪笔业务的什么环节轮到你了」，
  点「查看」直接跳到业务详情并自动标已读；支持「全部标为已读」。不依赖网络与配置，是兜底通道。

> ⚠️ 本机跑时出口 IP 会变，企业微信会报 60020。要稳定推送必须部署到固定 IP 的服务器。

## 八、银行回单上传与识别

- 入口：业务详情页 → 「银行回单」卡片（需要「收款登记 / 费用登记 / 录回单」权限）
- 支持 JPG / PNG / BMP / WEBP / PDF，文件存 `data/receipts/<业务单号>/`
- 图片上传后自动用**本地 tesseract** 识别（不联网、回单不外传），抽取：
  回单编号、金额、日期、付款账号
- 识别结果只做**建议值**展示，点「填入付款表单」才写进表单，最终以人工核对为准
- 依赖：本机需装 Tesseract-OCR（含 chi_sim 语言包）+ `pytesseract`、`pillow`

## 九、操作日志（仅管理员）

- 看板「最近动态」已关闭；所有流转留痕改到左侧「操作日志」
- 可按动作、操作人、日期、关键字筛选，支持导出 Excel
- 业务详情页的「流转记录」时间轴只对管理员与财务可见

## 十、删除规则

系统里能删的有五种，全部带二次确认，且都有引用保护：

| 删什么 | 谁能删 | 什么情况下会被拒 |
|---|---|---|
| 业务记录 | 有「删除业务」权限的人可删任意状态；其他人只能删自己的报批中单据 | — |
| 客户档案 | 有「维护 / 导入客户」权限 | 该客户名下已有业务记录 → 请改用停用 |
| 人员 | 有「人员与权限管理」权限 | 名下已有业务记录 → 请改用停用；不能删自己 |
| 部门 | 有「部门 / 字典维护」权限 | 部门下还有人员或业务 → 请改用停用 |
| 回单附件 | 有「收款登记 / 费用登记 / 录回单」权限 | — |

删业务时会连带清掉这笔业务的流程日志和 `data/receipts/<单号>/` 附件目录，不可恢复。
删部门时如果还有客户挂在该部门下，客户的归属部门会被自动置空（客户本身不删）。

### 业务列表的批量操作

列表页每行左侧有勾选框，表头与工具条各有一个「全选」框：

| 操作 | 效果 |
|---|---|
| 表头 / 工具条全选框 | 一次勾选本页所有可删记录（部分选中时显示为半选横杠） |
| 反选 | 把当前勾选状态整体取反 |
| Shift + 点击 | 从上次点击处连选到这次点击处，适合圈定连续一段 |
| 已选 N 项 | 实时显示数量；为 0 时「批量删除」自动置灰不可点 |
| 批量删除 | 一次删除所选记录，删完回到原来的筛选与页码 |

- 每行右侧另有单独的「删除」按钮，无需进详情页
- 无删除权限的行，勾选框为禁用态，删除按钮置灰并提示原因，鼠标悬停即可看到
- 批量删除会逐条复核权限：越权勾选的记录会被跳过，并在提示里说明跳过了几条
- 提示语随选中数量变化（「确认删除选中的 3 条业务？」），避免误删

客户档案用的是同一套交互（全选 / 反选 / Shift 连选 / 已选计数），只是动作换成「批量停用 / 批量启用 / 批量删除」三个按钮，共用同一次勾选。

## 十六、已知边界

- 管理员不能替人开账号，必须本人用管理员给的账号密码首次登录
- 停用某人后其账号立即无法登录（已登录的会话也会被清掉），要恢复只能重新启用
- 删除是不可恢复的，只留给纠错用；正常的人事变动与不再合作，一律用「停用」
- 导出按钮受权限控制，但导出本质是读取，能看数据的人在技术上都能拿到同样内容
- 本地 OCR 对版式复杂的回单准确率有限，识别结果必须人工核对
